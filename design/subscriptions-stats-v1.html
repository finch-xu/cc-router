这一版改了什么

  • 表格 → 订阅行。「状态」「被谁用」「用了多少」「还剩多少」一眼看完，详情不用进二级页，点行就地展开。
  • 状态写人话：冷却中带倒计时圆环；认证失败 / 限额满 / 缺 Key 不再只是一个小 pill。
  • 「需要处理」置顶：只列要人动手的（冷却会自愈，不进这里），每条一个直达按钮。
  • 「用于」把 used: 2 换成虚拟模型名 + 在该模型里的顺位，#1 高亮 = 主力。
  • 启停开关直接放在行尾；复制 / 测试连接 / 看请求日志收进展开区。

数据从哪来

  • 状态、可调度、冷却到期、限额、余额、槽位、slot_models_now：现有 SubscriptionDto。
  • 「用于」的顺位：useVirtualModels() 里各模型的有序订阅表，前端拼。
  • 行内 24 小时柱：需新增 get_subscription_activity（requests 表按订阅 × 小时聚合，24 格 × 成功/失败）。没有它时这一列退化为「今日 x 次 · 成功率」，取 useBreakdown("today","subscription")。
  • 顶部今日请求 / Token / 缓存：useOverallStats("today")。

细节

  • 排序「默认」= 需处理 → 可调度 → 冷却 → 停用，同组内按创建时间。
  • 停用行整体降为 50% 不透明度，只有状态和开关保持清晰。
  • System One 订阅显示 model-jev，与对话订阅同列表；筛选里单独一个「System One」芯片。
  • 窄屏（< 900px）行改两行堆叠，展开区单栏。

这一版改了什么

  • 时间范围提到页头，页面内一切（除全年）同口径；以前它夹在热力图和 KPI 之间。
  • 三张折线 / 柱图（请求 / Token / 耗时）合成主卡里一张图 + 切换；KPI 带「较上一周期」。
  • 环图 → 横条（和实时路由的 Token 卡同一种画法），可切虚拟模型 / 订阅 / 客户端。
  • 新增「请求用途」「耗时分布」；订阅表变成可点的行，直达请求日志。
  • 全年热力图挪到最后，并明确标注不受时间范围影响。

数据从哪来

  • KPI / 趋势 / Token / 虚拟模型 / 订阅 / 工具 / 全年：现有 useStatistics 各 hook，不改。
  • 较上一周期：需扩展 get_overall_stats 返回 previous（同长度的前一段，日聚合表上多算一次）。「全部」不显示对比。
  • 按客户端：tool_stats_daily.client_tool 已有；需新增按客户端的请求 / Token 聚合（或在 request_stats_daily 加维度）。
  • 用途 / 耗时分布：需新增，查 requests 原始表（purpose_kind 已落库），受保留期限制，所以卡片底部写清覆盖范围。

细节

  • 「今天」按小时 24 格；7 / 30 / 90 天按日；「全部」按周。
  • 耗时图：柱 = 平均，线 = P95；失败在请求图里叠在柱顶，用错误色。
  • KPI 的涨跌颜色按「好坏」而不是按方向：耗时上升 / 失败率上升是红。
  • 点任一分布行 → /request-logs?range=…&vm=…，和实时路由跳转同一套 URL 参数（lib/requestLogQuery.ts）。
